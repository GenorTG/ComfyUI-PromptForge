# PromptForge V2

V2 registers beside the legacy nodes. Existing node keys, execution code and saved
workflows are retained. ACE and audio-only workflows are unchanged.

## Pipe-free and pipe-chained

Every node runs without a pipe: connect standard ComfyUI `MODEL`, `CLIP`, `VAE`, `LATENT`,
`CONDITIONING`, `IMAGE`, `MASK`, `AUDIO`, `VIDEO` and `TEXT` sockets and it works like a
normal node. The pipe is optional and only carries the settings, presets, metadata and
inspection chain; where both exist the socket wins and the pipe contributes state.
Nodes that need the family take it from the connected model, and every value a node uses
is a widget, never a fixed branch.

## Node catalog

All entries use new `PROMPTFORGE_V2_*` keys. The current registration contains
50 V2 nodes.

| Area | Nodes and responsibility |
| --- | --- |
| Shared state | **Workflow Presets** captures/restores upstream widgets before queueing and passes the pipe through during execution. **LoRA Stack** loads multiple adapters with optional H3 audiovisual scopes. **Single LoRA** loads one user-selected adapter. **Run Inspect**, **Prompt Library**, and **Save Run Metadata** expose run configuration, reusable text, and optional metadata. |
| Media and image helpers | **Load Reference Image/Video/Audio** support file selection, enabled switches, role labels and descriptions. **Frame Interpolate** updates timing metadata. **Image Scale**, **Mask Prepare**, **Image Composite**, and **Image Result** support image edits and compositing. **Subject Mask** uses native SAM3. |
| Prompting | **Writer Model** loads a local writer lazily. **Image Prompt** and **H3 Prompt** each select raw text, an idea, or an action preset. Their respective **Prompt Writer** nodes add geometry/reference-aware context and validate affirmative output. **Prompt Inspect** displays text and validation/token diagnostics. |
| Shared image generation | **Image Model**, **Image Format**, **Image Sampling Settings**, **Image Encode**, **Image Sample**, **Image Decode**, **Image Save** support Krea 2, MOSS Image, and Anima. Krea edit-specific conditioning lives in **Krea Edit Prepare**. MOSS edit is intentionally omitted. |
| MiniMax H3 | **Model**, **Format**, **References**, **Reference Bank**, **Reference Select**, **Sampling Settings**, **Encode**, **Sample First Pass**, **First Pass Preview**, **Upscale Settings**, **Latent Upscale**, **Refine**, **Decode**, **Source Clip**, **Join**, and **Preview / Save** split the six generation modes and optional post stages. **Parts**, **Continuity**, and **Sequence** handle multipart generation. |

Nodes use a versioned pipe for configuration and pass live model/media artifacts
separately. Standard image, mask, latent, audio and video sockets are used at
stage boundaries where they aid inspection or connection.

## Start a workflow

Work in ComfyUI's normal workflow folder. `scripts/build_v2_workflows.py` regenerates
the set (UI plus `/prompt`-format API JSON and a manifest with the required choices).

Templates are intentionally blank. Select local model/encoder/VAE files, reference
files where applicable, and enter your own prompt before queueing. Edit LoRAs are
user-selected, never tied to a developer's filename. Automatic Krea reference masks
use a SAM3 checkpoint with its text encoder; manual masks can replace that stage.

Shared Image nodes support Krea 2, MOSS Image and Anima. Krea edit preparation is
specific to Krea. MOSS edit is excluded. H3 uses separate encoding, first sampling,
optional latent upscale/refinement, decoding, interpolation and saving stages.

## Prompts

Prompt selects raw text, an idea, or an action preset. Raw preserves text and skips
the lazy Writer Model branch. Idea/action routes require a local writer. Format
and References precede the writer so it receives output geometry, timing and
reference roles. Prompt Inspect shows the final text and diagnostics.

Enhanced descriptions must pass affirmative-wording and output-format validation.
Exhausted repairs raise an error before encoding. In-scene quoted dialogue and
required H3 sentinel fields are treated separately. Raw text is linted without
being rewritten. Actual negative conditioning remains separate from positive text.

## Presets and references

Workflow Presets captures connected upstream V2 settings before queueing, using
stable roles and named widgets. Apply restores supported settings in one undo
transaction. Connected widget inputs are skipped with a report. The node passes
the exact pipe object through during execution.

Reference filenames, role selectors and LoRA choices are included; prose is
excluded unless Include Text is enabled. Media payloads and live models are never
stored in presets. Export/import preset JSON for reuse with matching workflow roles.

Reference image/video/audio loaders have enable switches and a file picker. H3
Reference Bank and Reference Select provide named reusable media selections.
Selecting a different reference set does not require rewiring its consumers.

LoRA Stack works across families. Select audiovisual layer controls to expose
video/audio scopes. Local sidecars and the optional LoRA Manager listing enrich
discovery; the stack does not require LoRA Manager. Single LoRA is the simpler
user-selected adapter loader.

## Timing and output

H3 generation uses its native 24 FPS and valid frame grid; Format reports the
resolved duration. Frame Interpolate is disabled by default. When enabled, it
preserves video duration and updates output FPS in the pipe. The saver uses that
rate automatically, while native generation FPS remains available separately.

Preview / Save can write temporary previews or final video. A first-pass branch
can be inspected independently of refinement. Multipart templates use Parts,
Continuity and Sequence, rather than adding sequence controls to single clips.

## Verification

The integration targets the inspected ComfyUI 0.44.0 and frontend 1.58.5. Older
versions may lack the native H3, Krea, SAM3 or V3 APIs used by this suite.

Checks can be reproduced with ComfyUI's Python environment:

```bash
python scripts/check_v2_runtime.py --comfy-root /path/to/ComfyUI
python -m unittest discover -s tests -p test_v2_contracts.py
python -m unittest discover -s tests -p test_v2_prompting.py
python -m unittest discover -s tests -p test_v2_h3.py
node tests/promptforge_v2.test.mjs
python scripts/build_v2_workflows.py --object-info /path/to/object_info.json
```

For browser checks, start an isolated ComfyUI instance and pass the generated UI
files with `--workflow`; the browser script checks widget values, node roles,
frontend rendering and saved node-size stability.

The inspected ComfyUI 0.44.0 frontend loaded all 15 generated templates, checked
named-widget values and role IDs, and reloaded each graph without changing node
sizes. Contract, prompt, runtime, H3 and frontend tests pass (4, 7, 14, 14 and
17 checks respectively). The isolated browser also queued a tiny built-in
32×32 ComfyUI image job; it did not run V2 model inference.

Runtime checks use an isolated temporary ComfyUI setup with only this custom
pack. Controlled inputs and tiny models test execution contracts; they do not
establish real-checkpoint image quality, identity preservation or long-video
stability. Full generation and SAM3 mask quality still require testing with the
selected model artifacts and hardware. Template manifests distinguish structural
validation from generation testing.
