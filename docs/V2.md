# PromptForge V2

V2 registers beside the legacy nodes. Existing node keys, execution code and saved
workflows are retained. ACE and audio-only workflows are unchanged.

## Pipe-free and pipe-chained

Every node runs without a pipe: connect standard ComfyUI `MODEL`, `CLIP`, `VAE`, `LATENT`,
`CONDITIONING`, `IMAGE`, `MASK`, `AUDIO`, `VIDEO` and `TEXT` sockets and it works like a
normal node. The pipe is optional and only carries the settings, presets, metadata and
inspection chain; where both exist the socket wins and the pipe contributes state.
Nodes that need the family take it from the connected model, and every value a node uses
is a widget, never a fixed branch.

## Node catalog

All entries use new `PROMPTFORGE_V2_*` keys. The current registration contains
54 V2 nodes.

Nodes use a versioned pipe for configuration and pass live model/media artifacts
separately. Standard image, mask, latent, audio and video sockets are used at
stage boundaries where they aid inspection or connection.

## Start a workflow

Work in ComfyUI's normal workflow folder. `example_workflows/v2` holds each template as
UI and `/prompt`-format API JSON with a manifest of the required choices.

Templates are intentionally blank. Select local model/encoder/VAE files, reference
files where applicable, and enter your own prompt before queueing. Edit LoRAs are
user-selected, never tied to a developer's filename. Automatic Krea reference masks
use a SAM3 checkpoint with its text encoder; manual masks can replace that stage.

Krea Edit Prepare takes one identity mask per reference (`mask` for the first picture,
`mask_b` for the second). The text encoder then sees only the masked area on grey, so a
photo's clothes and room do not carry over, and `ref_boost_a` / `ref_boost` weight the
first / last reference inside its mask only. The single-reference edit uses "face, hair and
neck" with weight 4. The two-reference template uses the same masks with weight 2 and
places both references with `beside`: laid over the picture (`aligned`) they paste their own
background and limbs into the result, and `bag` lost the likeness in tests. `crop_to_mask`
crops each masked reference to its face area first and is on in the two-reference template:
in a 5-pose x 8-setting sweep scored with ArcFace it raised the woman's likeness from 0.37 to
0.64 and the man's from 0.69 to 0.76 and never lost a face. `grounding_px` (default 768), the
weights and the identity LoRA strength gave no comparable gain.

Shared Image nodes support Krea 2, MOSS Image and Anima. Krea edit preparation is
specific to Krea. MOSS edit is excluded. H3 uses separate encoding, first sampling,
optional latent upscale/refinement, decoding, interpolation and saving stages.

## Prompts

Prompt selects raw text, an idea, Idea Advanced, or an action preset. Raw preserves text and skips
the lazy Writer Model branch. The other routes require a local writer. Idea Advanced stores its items as JSON in
the `idea_advanced` widget; `v2/idea_advanced.py` writes them out as one request, which the writer then treats as
an idea (`source` `idea`, `origin` `advanced`) and checks for the spoken lines. Saved presets are one pool per
source, served by `/promptforge/v2/prompt-presets`. Format
and References precede the writer so it receives output geometry, timing and
reference roles. Prompt Inspect shows the final text and diagnostics.

Action presets are JSON under `presets/actions`. `image_actions.json` and
`h3_actions.json` ship with the pack; `image_actions_extra.json` and
`h3_actions_extra.json` hold user and NSFW presets, are created on first save and are
gitignored. Both are cached by file mtime, so hand edits apply without a restart.

Enhanced descriptions must pass affirmative-wording and output-format validation.
Exhausted repairs raise an error before encoding. In-scene quoted dialogue and
required H3 sentinel fields are treated separately. Raw text is linted without
being rewritten. Actual negative conditioning remains separate from positive text.

## Presets and references

Workflow Presets captures connected upstream V2 settings before queueing, using
stable roles and named widgets. Apply restores supported settings in one undo
transaction. Connected widget inputs are skipped with a report. The node passes
the exact pipe object through during execution.

Reference filenames, role selectors and LoRA choices are included; prose is
excluded unless Include Text is enabled. Media payloads and live models are never
stored in presets. Export/import preset JSON for reuse with matching workflow roles.

Reference image/video/audio loaders have enable switches and a file picker. The Reference Manager holds the ordered pictures, videos and voices with names and descriptions; its `names` input picks a subset per run, and extra media sockets add generated pictures, videos and audio.
Selecting a different reference set does not require rewiring its consumers.
A scene picture in the reference set competes with the people for the position: in tests a harbour background turned a missionary clip into two people reclined side by side, while the same references without it kept the position. Describe the place in the prompt instead.

LoRA Stack works across families. Select audiovisual layer controls to expose
video/audio scopes. Local sidecars and the optional LoRA Manager listing enrich
discovery; the stack does not require LoRA Manager. Single LoRA is the simpler
user-selected adapter loader.

Each LoRA row can be limited to its feed-forward layers ("ff only") and cut to a
lower rank (`rank`, 0 keeps its own). Both are off by default. They make a high-rank
LoRA trained on another base work as a soft motion or concept reinforcer on a
fine-tune whose attention it would otherwise damage (for example base-H3 LoRAs on an
H3 fine-tune). Single LoRA has the same two options as `mlp_only` and `max_rank`.

## Model profiles

The Image Model node remembers sampler settings per checkpoint. Picking a model by
hand applies its profile (steps, CFG, sampler, scheduler) to the workflow's single
Sampling Settings node and leaves prompts, LoRAs and every other setting alone;
the `auto` checkbox turns that off and "Apply profile" applies it on demand.
`presets/model_profiles.json` ships the creators' recommendations for the Krea, MOSS
and Anima checkpoints (entries marked "assumed" had no creator numbers). "Save as
profile" stores your current settings in the gitignored
`presets/model_profiles_user.json`; "Forget mine" returns to the shipped entry.
Profiles match across quantisation names, so an `int8` and a `convrot` file share one.

The H3 Model node does the same for MiniMax H3 checkpoints: picking one by hand writes its
sampling profile (steps, CFG, sampler, scheduler, sigma shifts, second-pass settings) into
the H3 Sampling Settings node and shows a toast. The pack ships the defaults used for the
PRISM checkpoint and assumed profiles for Eros Max 8-step Turbo (LCM, simple, video shift
12, audio shift 3) and DaSiWa Turbo (euler, simple, video shift 10, audio shift 4), taken from
the makers' notes. The Eros maker also recommends 10% sparse attention for v1.0 (Performance node,
`sparse_attention` on, `keep_percent` 10); without it that checkpoint can flicker.

## Reference focus

Each picture card in the Reference Manager, and Load Reference Image, can zoom onto one
subject of a picture (`focus`: face and hair, face, whole person, or your own words). SAM3
finds it (a checkpoint with its text encoder in `models/sam3`) and the picture is cropped
to the box around it, widened by `focus_padding`; the surroundings inside the box stay.
Choosing a grey, white or black background also cuts the subject out. The card's preview
button shows what the model receives; it waits while a generation is running. Words that
match several things, such as `person` in a picture of two people, box all of them.
Off by default; pictures only.

## Writer prompt length

Both Prompt Writer nodes are uncapped by default: no word or tag ranges are given to the
writer, and it may use at least 8192 tokens. Set the `length_words` slider above 0 to ask
for at most that many words (tags for Anima). Multipart Sequence always writes uncapped.

## Timing and output

H3 generation uses its native 24 FPS and valid frame grid; Format reports the
resolved duration. The H3 templates start at 16:9 and 0.5 MP, upscale the latent
to twice the pixels, refine it, and run Frame Interpolate x2. Frame Interpolate
preserves video duration and updates output FPS in the pipe. The saver uses that
rate automatically, while native generation FPS remains available separately.

Frame Interpolate's `auto` switch (off by default on the node, on in the H3 templates) streams one frame pair at a time through the GPU: it is
faster than the batched runs and needs no batch size.

Long clips do not need to fit in memory: Decode, Frame Interpolate, Join and Video
Cleanup move a clip that does not fit in RAM to ComfyUI's temp folder, and
sampling, encoding and upscaling unload everything and try once more on out of GPU
memory.

Decode can take the soundtrack from the first or the second pass (`audio_from`);
the second pass reworks the audio, and some checkpoints sound better before it.

Preview / Save can write temporary previews or final video. A first-pass branch
can be inspected independently of refinement. Multipart templates use Parts,
Continuity and Sequence, rather than adding sequence controls to single clips.

`encoder_preset` fills in the encoder widgets: **high quality** (x265 slow, 10-bit), **balanced** (x264, 8-bit),
**small file**, **lossless-ish**, **fast (GPU)** (h265 nvenc, 10-bit) and **compatible** (h264 nvenc, 8-bit). The
widgets stay editable. h264 nvenc offers 8-bit only; a saved or API workflow that asks it for 10-bit is saved 8-bit.

## Verification

The integration targets the inspected ComfyUI 0.44.0 and frontend 1.58.5. Older
versions may lack the native H3, Krea, SAM3 or V3 APIs used by this suite.

The tests and the template builder live on the repository's `dev` branch (`tests/`,
`scripts/`); they are not part of releases or the registry package.

The inspected ComfyUI 0.44.0 frontend loaded all 15 generated templates, checked
named-widget values and role IDs, and reloaded each graph without changing node
sizes. Contract, prompt, runtime, H3 and frontend tests pass (4, 7, 14, 14 and
17 checks respectively). The isolated browser also queued a tiny built-in
32×32 ComfyUI image job; it did not run V2 model inference.

Runtime checks use an isolated temporary ComfyUI setup with only this custom
pack. Controlled inputs and tiny models test execution contracts; they do not
establish real-checkpoint image quality, identity preservation or long-video
stability. Full generation and SAM3 mask quality still require testing with the
selected model artifacts and hardware. Template manifests distinguish structural
validation from generation testing.


## MiniMax H3: settings that tested best (PRISM main model)

Judged frame by frame on the 5.2 s ref2v clips, 0.5 MP first pass and 1 MP second pass:

- Give the woman a naked reference (make one with the Krea Edit identity mode). A clothed photo
  leaks its clothes into sex scenes whatever the writer is told.
- Use the action's own framing: 16:9 for missionary, doggy and oral, 9:16 for cowgirl and the
  kneeling blowjob. A square frame made the model stack extra male heads; the close-up and
  hip-level cameras gave frontal views where the entry point is ambiguous.
- Mystic (ref2va) and PenisV2 LoRAs at 0.5 each add detail and expression to PRISM; keep other
  concept LoRAs at 0.2-0.6.
- Eros Max v1.0: LCM + simple, 8 steps, shift 12/3, and 10% sparse attention in the Performance
  node (the maker's advice; the templates used for these tests bypassed the Performance node, so
  it was not in effect). DaSiWa Turbo: euler + simple, shift 10/4, 8 steps. Both profiles ship as assumed.
- The writer is told to write only what the brief or the pictures give, and never a picture's
  room, water, clothes or pose.


## Krea 2 Edit: two reference photos

With two Krea references the writer switches by itself to the "Krea 2 Edit - Two People" template.
The prompt starts with one short identity sentence per photo in photo order ("The man from the first
photo: ..." / "The woman from the second photo: ..."), then the request in the user's own order and
words, with "reference 1 / 2" turned into "the man" and "the woman". Facts the user states about a
person (a tattoo, a piercing, hair) go into that person's sentence; nothing the request does not state
is added (no extra acts, guests, props or ambience).

The writer is shown the same masked face-and-hair crops on grey that the image encoder sees, so a
photo's room, water, clothes and body ink cannot leak into the text. The penetration or oral/hand rule
is only kept in the template when the request names such an act.

Text-only checks (8 requests x 3 seeds, 9B writer, no images): 18 of 24 prompts passed a strict linter
(anchor order and length, the right traits for the right person, no photo clothes or water, no
invented acts or atmosphere, all user facts kept). The rest were an occasional "no visible marks"
phrase in a woman's line or an identity line a few words over its limit.
